# AGENTS.md

This file contains instructions for agentic coding agents working on this Bridgetown portfolio site.

## Project Overview

This is a Bridgetown 2.2 static site generator project for a personal artist portfolio. The site uses:
- Bridgetown (Ruby) for static site generation
- ERB as the template engine (no Liquid)
- Tailwind CSS v4, precompiled at build time via PostCSS + esbuild
- Vanilla JavaScript (no frameworks)
- Spanish language content

## Build and Development Commands

```bash
# Install dependencies (Ruby gems + Node packages)
bundle install
npm install

# Development server (runs at http://localhost:4000)
# Also watches and rebuilds the Tailwind CSS
bin/bridgetown start

# Build for deployment (precompiles Tailwind, then generates the site into output/)
bin/bridgetown deploy

# Build the site only (assumes frontend assets were built already)
bin/bridgetown build

# Compile Tailwind CSS manually
npm run esbuild        # one-off, minified
npm run esbuild-dev    # watch mode

# Generate responsive WebP variants (required after adding images)
bin/images             # generate missing/outdated variants
bin/images --check     # verify variants exist (CI guard)

# Clean generated files
bin/bridgetown clean
```

## Testing

No automated testing framework is configured. Testing should be done manually by:
1. Running `bin/bridgetown start` and testing in browser
2. Checking responsive design at different viewport sizes
3. Verifying lightbox gallery functionality
4. Testing mobile menu and scroll animations
5. Checking `/`, `/full-portfolio/`, and `/404.html`

## Code Style Guidelines

### File Organization
- Site content lives in `src/`
- Layouts in `src/_layouts/`, partials in `src/_partials/`, data in `src/_data/`
- Tailwind entrypoint in `frontend/styles/index.css`
- Site configuration in `config/initializers.rb`
- Roda development server in `server/roda_app.rb`
- Static assets in `src/assets/` (copied verbatim to the output)
- Build output goes to `output/` (gitignored)

### HTML/ERB Conventions
- Use semantic HTML5 elements
- `<%= expression %>` outputs a value; `<% code %>` runs logic with no output
- Layouts receive the page content via `<%= yield %>`
- Render partials with `<%= render "navbar" %>` (partial files use a leading underscore, e.g. `_navbar.erb`)
- Page metadata comes from front matter: `data.title`, `data.description`
- Site metadata lives in `src/_data/site_metadata.yml`: `site.metadata.title`, `site.metadata.description`
- Use `relative_url` for internal links and asset paths: `<%= relative_url '/assets/images/logo.webp' %>`
- Use `asset_path :css` for the compiled stylesheet
- Front matter uses YAML between `---` lines and still supports `layout`, `title`, `description`, `permalink`
- Spanish language content: `lang="es"` on HTML element
- Mobile-first responsive design with Tailwind utilities

### CSS/Styling
- Tailwind CSS v4 is configured in `frontend/styles/index.css` using CSS-first `@theme` tokens
- There is no `tailwind.config.js`; add colors, fonts, and other design tokens inside `@theme`
- Utilities are generated by scanning `src/**/*.{html,erb,md}` and `src/assets/js/**/*.js` (`@source` directives)
- Custom color palette: `blush`, `rose-light`, `cream`, `rose-gold`, `dusty-rose`, `soft-pink`, `dusty-sage`, `soft-cream`, `muted-rose`, `aqua-teal`, `warm-ivory`, `sage-green`, `soft-gray`, `pale-aqua`, `muted-coral`, `deep-teal`
- Custom fonts: Playfair Display (serif), Quicksand (sans-serif)
- Fonts are **self-hosted**: the woff2 files live in `src/assets/fonts/` and are declared with `@font-face` in `frontend/styles/index.css`. Never add Google Fonts (or any third-party font CDN) back to the layout — the preload in `src/_layouts/default.erb` points at the local Playfair file.
- Put custom CSS (animations, lightbox, reveal effects, video facades) in `frontend/styles/index.css`, never in the layout
- The compiled stylesheet is fingerprinted and served from `/_bridgetown/static/`

### JavaScript Conventions
- Use modern ES6+ JavaScript
- camelCase for variables and functions: `mobileMenuBtn`, `initLightbox()`
- kebab-case for CSS classes and IDs: `mobile-menu`, `lightbox-img`
- Use defensive programming with element existence checks
- Add JSDoc-style comments for functions
- Event-driven architecture with `DOMContentLoaded` listener
- Prefer `IntersectionObserver` for scroll reveals and one `requestAnimationFrame`-throttled, passive scroll handler. Never read layout (`offsetTop`, `getBoundingClientRect`) in a scroll handler without caching.
- Gallery/lightbox interactions use `data-lightbox` attributes and event delegation — do not add inline `onclick` handlers.
- `src/assets/js/main.js` is served as a plain static file (not bundled)

### Import Patterns
- No ES6 imports/exports in site JavaScript - use global scope
- Include ERB partials with `<%= render "partial_name" %>`
- Fonts are self-hosted (see `src/assets/fonts/`); do not load external CSS from a CDN
- Place site JavaScript in `src/assets/js/main.js`

### Error Handling
- Use simple validation with user-friendly alerts (in Spanish)
- Check element existence before DOM manipulation
- Use optional chaining for safe property access
- Provide fallback behavior for missing elements

### Naming Conventions

#### Files and Directories
- **Files**: kebab-case (`main.js`, `full-portfolio.html`)
- **Layouts/partials**: `.erb` extension (`default.erb`, `_navbar.erb`)
- **Directories**: lowercase with underscores (`_layouts`, `_partials`)
- **Bridgetown special directories**: underscore prefix (`src/_data`, `src/_layouts`)

#### Ruby/ERB
- **Variables/Methods**: snake_case (`site_metadata`, `portfolio_images`)
- **CSS Classes/IDs**: kebab-case (`mobile-menu-btn`, `nav-link`)

#### JavaScript
- **Variables/Functions**: camelCase (`highlightNav`, `updateNavbar`)
- **Constants**: UPPER_SNAKE_CASE (if needed)
- **CSS Classes/IDs**: kebab-case (`mobile-menu-btn`, `nav-link`)

#### HTML/ERB
- **IDs/Classes**: kebab-case (`lightbox-img`, `mobile-menu`)

## Performance Guidelines

- Tailwind CSS is precompiled at build time (no runtime CDN script)
- Fonts are self-hosted and the Playfair face is preloaded; never reintroduce a third-party font request on the critical path
- Every content image declares `width`/`height`, uses `loading="lazy"` below the fold, `decoding="async"`, and a `srcset`/`sizes` pair built from the generated variants
- Video cards are poster facades (`data-video`): the poster is a lazy `<img>` and the MP4 only loads when the visitor clicks play
- Use one passive, `requestAnimationFrame`-throttled scroll handler and prefer `IntersectionObserver`; do not read layout in scroll callbacks
- The compiled stylesheet stays external: it is small, fingerprinted, and cacheable. Do not inline it into every page
- GitHub Pages sends `Cache-Control: max-age=14400`. The site is proxied by Cloudflare, so longer browser/edge cache rules for `/_bridgetown/static/*` and `/assets/*` are configured in the Cloudflare dashboard, not in this repo

## Deployment

- The site is deployed to GitHub Pages through `.github/workflows/deploy.yml`
- A push to `main` runs `bin/bridgetown deploy` (Tailwind precompile + site build), uploads `output/` as a Pages artifact, and deploys it with `actions/deploy-pages`
- CI runs `bin/images --check` before building, so a missing responsive variant fails the deploy instead of shipping broken `srcset` candidates
- GitHub Pages must be configured in the repository settings with Source: **GitHub Actions**
- The custom domain is `ezcurdia.art` (configured in the repository's Pages settings; `src/CNAME` documents it)
- Test thoroughly before merging to `main`

2. Use event listeners and defensive programming
3. Test functionality across devices

### Updating Content
1. Edit the appropriate file in `src/`
2. Maintain Spanish language consistency
3. Update meta descriptions via front matter if needed

## Image Processing (Portfolio)

All portfolio images live in `src/assets/images/portfolio/` as `.webp` files. No other formats are accepted in this directory.

### Source files

Raw camera files (JPG, HEIC, PNG, RAW) live in `src/assets/images/` as a staging area. After conversion they may be deleted.

### Conversion spec

| Parameter | Value |
|---|---|
| **Format** | WebP, lossy (VP8/VP8X). Never lossless. |
| **Long edge** | 1920 px. Short edge scales proportionally. |
| **Aspect ratio** | Preserve original from source. Never force-crop. |
| **Quality** | `cwebp -q 80` (default). Adjust only if file > 300 KB. |
| **Target file size** | ≤ 300 KB per image. |

### Naming convention

Originals preserve the original camera filename (numeric). Responsive variants append `-<width>w` before the extension.

| Pattern | Use |
|---|---|
| `IMG_NNNN.webp` | iPhone / digital cameras |
| `DSC_NNNN.webp` | DSLR / mirrorless |
| `kebab-case.webp` | Work-in-progress, scans, non-numbered sources |
| `DSC_NNNN-480w.webp` | Generated variant (do not edit by hand) |
| `kaerus-poster-640w.webp` | Generated video poster variant |

### Responsive variants

`bin/images` creates every variant; it is the only supported way to generate them:

| Source | Variants | Used by |
|---|---|---|
| `src/assets/images/portfolio/*.webp` | `-480w`, `-960w` | Homepage grid and full portfolio masonry |
| `src/assets/videos/*-poster.webp` | `-320w`, `-640w` | Video facades |
| `src/assets/images/photo.webp` | `-1024w` | About section |

Variants are committed to the repo. Run `bin/images` after adding or replacing an original, then `bin/images --check` to confirm nothing is missing. The lightbox always opens the full-size original.

### Processing commands

```bash
# Long edge 1920, preserve aspect ratio (originals only)
cwebp -q 80 -resize 1920 0 input.jpg -o output.webp

# Generate or refresh every responsive variant
bin/images

# Verify output
identify -format '%f %wx%h %b\n' output.webp
```

### Validation checklist

Before committing a new batch:
1. All files in `src/assets/images/portfolio/` are `.webp`
2. Originals have a 1920 px long edge (`identify -format '%w %h' file.webp`)
3. No original or variant exceeds 300 KB
4. Original filenames match the source (minus extension)
5. `bin/images` ran and `bin/images --check` passes
6. Source files in `src/assets/images/` are cleaned up after conversion

### Gallery auto-discovery

`src/full-portfolio.html` auto-discovers originals in ERB and ignores generated variants:

```erb
<% variant_pattern = /-\d+w\z/ %>
<% all_images = site.static_files
  .select do |file|
    file.relative_path.to_s.start_with?("/assets/images/portfolio/") &&
      file.extname == ".webp" &&
      !File.basename(file.name, ".*").match?(variant_pattern)
  end
  .sort_by(&:name)
  .reverse %>
```

Use `file.relative_path` (not `file.path`) when building URLs: `file.path` is an absolute filesystem path and produces broken links. No manual registration is needed — dropping an original `.webp` into the directory makes it appear in the gallery once its variants exist.
